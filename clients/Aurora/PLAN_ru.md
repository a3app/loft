# План · loft на ОС Аврора

[English](PLAN.md) · **Русский** · [中文](PLAN_zh.md)

ПО 1.0.0. Протокол 1.0. План версии не повышает.

## Цель

Клиент loft / SSTP / VLESS / Trojan на телефоне с ОС Аврора как системная сессия оверлея. Пользователь импортирует ключ (`loft://`, `sstp://`, `vless://`, `trojan://`, `.loft`), нажимает Подключить — трафик устройства идёт в сессию. На loft смена Wi-Fi / LTE сохраняет IP оверлея (свежий `0x02`, тот же `instance_id`).

ОС владеет TUN (`connman-vpnd`). Loft владеет каналом (фронты). GUI — Qt/QML Silica.

## Вне рамок

- gomobile / `clients/mobile`. Аврора — GNU/Linux; сессия — `loft-front`, как на macOS.
- Qt Widgets. В публичном API Авроры — Qt Quick + Silica.
- Flutter как первый GUI. Сначала родной QML; Flutter можно позже.
- SOCKS5 как вход, которым пользуются чужие приложения. Фаза 1 может поднять SOCKS для проверки; вход продукта — TUN ConnMan.
- Несколько оверлей-сессий сразу (ConnMan держит одну активную строку).
- IKEv2 / OpenVPN / WireGuard внутри этого приложения. Это штатные типы Настроек. SSTP — Go в том же loft-front, когда подключим.
- Листинг RuStore / магазина Авроры в первой выкладке (достаточно sideload RPM).
- Dist / RPM в GitHub Release `v*` до следующего тега.

## Фазы

### 0. Каталог — это дерево

Документы, план, HTML-макет ([design/](design/)). Тонкий хост QML вставляет YAML.

### 1. Тонкий хост + loft-front

Кросс `loft-front` `linux/arm64` (и `arm`, если устройство просит). Приложение пишет `client.yaml` и запускает помощник. SOCKS на loopback для проверки в браузере. TUN ещё нет.

Проверка: Hello, IP оверлея в приложении, curl через SOCKS.

### 2. Плагин VPN ConnMan — написан

Штатное расширение Авроры: `.so` ConnMan (`loft-plugin.c`) + помощник `loft-connman` (exec `loft-front -tun NAME -tun-noexec`) + `loft-script` notify с IP / DNS / MTU оверлея. `connman-vpnd` создаёт tun и маршруты. Петля: `Host` → `trusted_ip` (фронт мимо tun), как на macOS.

Настройки → Сеть грузят `settings/{listitem,edit,advanced,details}.qml`, тип — **Loft**. Хост QML сначала D-Bus `net.connman.vpn` Create/Connect; SOCKS `loft-front` — запасной путь, если плагина нет.

Проверка (нужно устройство): ping шлюза оверлея; штатный браузер идёт с IP оверлея. `.so` собирается только в SDK Авроры.

### 3. Профили и политика машины

YAML-профили в `~/.local/share/app.loft.aurora/`. Импорт/экспорт `.loft`. Один активный профиль (одна строка ConnMan).

- Удержание: default ConnMan остаётся занятым, пока сессия лежит (копирайт: *маршрут* / *прямой интернет*).
- Сплит: списки зон → маршруты ConnMan `via` / `direct`. Направление живёт на зоне.
- Сканер: камера QR + файл. Детектор: `loft://`, `sstp://`, `vless://`, `trojan://`, YAML / `.loft`. Схема `loft`. Подтверждение, потом запись. Подпись в списке: тип · транспорт · хост.
- Обложка: лампа + Подключить/Отключить.

### 4. Пакет

Подписанный RPM для aarch64 (и armv7hl, если нужно). Аврора SDK (`mb2` / Aurora IDE). Sideload на устройство разработчика достаточно, чтобы кормить собаку. Job в Actions — позже, не в первом теге.

## Порядок работ в дереве Go

1. Сессия — процесс `loft-front`. Общие `-tun NAME` и `-tun-noexec` (подключить, без addr/routes). Флагов только под Аврору нет.
2. Кросс: `GOOS=linux GOARCH=arm64 CGO_ENABLED=0` из этого Makefile. Если glibc устройства откажется — пересборка в Build Engine SDK.
3. Смена пути: ConnMan / Qt Network → loft-front уже поднимает свежий `0x02` и тот же `instance_id`. Caps не добавляем.
4. `clients/mobile` под Аврору не биндим.

## Риски

| Риск | Как закрываем |
|------|----------------|
| Песочница Regular не открывает TUN | Фаза 2 идёт через плагин ConnMan; GUI `/dev/net/tun` не трогает. |
| Плагину нужен привилегированный RPM | Профиль безопасности в доке; сначала sideload. |
| glibc / статический Go | Сначала `CGO_ENABLED=0`; иначе gcc+cgo в SDK. |
| Петля GET/WS в tun | IP фронтов исключить до default, как на macOS. |
| Модерация магазина | Sideload до следующего тега. В копирайте loft, не чужой бренд. |
| Нет устройства | Эмулятор для QML; дым TUN — на железе. |

## Готово когда

Участник на ОС Аврора 5.x импортирует `.loft` или `loft://`, нажимает Подключить, видит лампу, штатный браузер идёт с IP оверлея. Смена Wi-Fi → LTE этот IP сохраняет.
