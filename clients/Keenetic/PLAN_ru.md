# План · loft на KeeneticOS

[English](PLAN.md) · **Русский**

ПО 1.0.0. Протокол 1.0. План версии не повышает.

## Цель

Маршрутизируемый клиент loft на Keenetic: **одно подключение** в приоритетах и раздельной маршрутизации. Токен и фронты — на LAN-странице, вход — сессия веб-админки Keenetic.

## Вне рамок

- Родной тип «Добавить loft» рядом с WireGuard (нужен компонент NDM от Keenetic).
- Патч JS стокового `:80` как форма настроек.
- SSTP / WireGuard / OpenVPN в этом пакете.
- Именованные списки loft как мозг сплита на роутере (это DNS-маршруты и политики Keenetic).

## Фазы

### 0. Каталог — это дерево

Документы, план, HTML-макет. Демона нет.

### 1. Сессия на TUN

Кросс-сборка `loft` под linux `aarch64` / `armv7` / `mipsel` (`CGO_ENABLED=0`). Init в `/opt/etc/init.d/`. YAML в `/opt/etc/loft/client.yaml`.

- `listen.tun: auto`, `default_route` / kill-switch **выкл**.
- После Status: `ndmc` создаёт/обновляет `OpkgTun0` (описание Loft, IP оверлея, MTU, `up`).
- Хостовые маршруты IP исходящих через интерфейс провайдера (без петли).
- Стоп: `OpkgTun0` down, процесс уходит.

Проверка: ping шлюза оверлея; Keenetic показывает Loft в приоритетах.

### 2. Панель + сессия Keenetic

HTTP только LAN (`:8090` по умолчанию). Пароля loft нет.

- Прокинуть `Cookie` браузера на `127.0.0.1/auth` (или `/rci/show/system`). 200 — страница; 401 — редирект на стоковый логин с URL возврата.
- Требовать configurator/admin, не гостя.
- Слушать LAN IP и `127.0.0.1`. На KeenDNS не публиковать.
- `localhost:79` (RCI без пароля) в браузер не отдавать.

KeeneticOS 5.2: если `/auth` объявляет `x-ndw4-authenticate`, брать одноразовый токен по редиректу.

UI v1: статус (вкл/выкл, IP оверлея, фронт, байты), правка (токен, URL, тип, путь, cdn, fingerprint), старт/стоп. Фронты только loft.

### 3. Пакет

`.ipk` на три архитектуры Entware. `postinst` один раз регистрирует OpkgTun. `prerm` снимает. README: OPKG, TUN/TAP, KeeneticOS 5.0+. Job в Actions — позже, не в первом теге.

### 4. VLESS

Второй тип исходящего в том же процессе и том же OpkgTun. В панели блок VLESS (UUID, SNI, reality). loft остаётся по умолчанию. Второго интерфейса NDM нет.

## Порядок в дереве Go

1. Флаг или YAML: «режим Keenetic» = TUN вверх, без default route, хук с IP/MTU/шлюзом оверлея.
2. `RememberGateway` уже есть; им же пинить exclude-хосты.
3. Панель — новый `clients/Keenetic/cmd` (или `loft -panel`), чтобы `loft-front` остался процессом сессии macOS.

## Риски

| Риск | Как закрыть |
|------|-------------|
| RSS Go на 128 МиБ | Сначала aarch64 (Giga/Peak/Hopper). Замерить RSS до mipsel. |
| Нет OpkgTun на 4.x | Документировать 5.0+. Старт с понятным логом отказать. |
| Cookie не уходит на :8090 | Тот же хост, `Path=/`. Запас: прокси `/auth` на :8090. |
| Редизайн веба прошивки | Панель `:80` не патчит. Ссылка на дашборде — по желанию и с версией. |
| Петля | Пинить IP фронтов на ISP до `0/0` через OpkgTun. |

## Готово, когда

Оператор на KeeneticOS 5.x с Entware ставит ipk, вставляет ключ участника, видит **Loft** в приоритетах, назначает политику — и устройства в ней выходят через loft.
