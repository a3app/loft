# Loft · клиент Windows

[English](DESIGN.md) · **Русский** · [中文](DESIGN_zh.md)

Агент в области уведомлений (трей); окно вторично. Знак, палитра и шрифт: [`brand/`](../../../docs/brand/). Интерактивный макет: [`index.html`](index.html). Протокол: [docs/protocol_ru.md](../../../docs/protocol_ru.md).

Клиент повторяет macOS v1: [`../../macOS/design/DESIGN_ru.md`](../../macOS/design/DESIGN_ru.md). Продукт (§1), поддержка протокола (§2), профили (§3), маршрут и TUN (§4), split routing (§5), первый запуск (§8), главное окно (§9) и тексты (§10) — те же. Здесь описано только то, чем Windows отличается.

---

## 1. Платформа

Минимальная версия — **Windows 7**. Вид на 7, 8.1, 10 и 11 одинаковый: интерфейс рисует само приложение. Mica, Acrylic, Aero Glass, системная тема и системный акцентный цвет не используются. Фон окон — Ink `#1A1714`, акцент — лампа.

Шрифт UI — **Segoe UI** (есть в Windows начиная с Vista). Avenir Next не вшивается. Начертания — как у бренда: заголовки Semibold 600, кнопки и вкладки 500, текст Regular 400. Слово `loft` в окне «О программе» — Segoe UI цветом лампы: в SVG бренда пока элемент `<text>`, контуры в v1 не обводятся. Моноширинный шрифт — Consolas.

Сборки: **x86 и x64**. UI — **нативный Win32** с собственной отрисовкой (без WebView и без системных тем оформления).

## 2. Трей

Значок — [`docs/brand/svg/loft-tray.svg`](../../../docs/brand/svg/loft-tray.svg): тело Snow `#F3EDE4`, окно — лампа (правило бренда 4); на светлой панели задач тело Ink (`loft-tray-light*`). Растры — [`docs/brand/tray/`](../../../docs/brand/tray/): 16 / 20 / 24 / 32 px для масштаба 100 / 125 / 150 / 200 %. Вниз из 1024 не масштабировать (правило 2).

| Состояние | Тело | Окно |
|-----------|------|------|
| disconnected | snow | snow (`loft-tray-off`) |
| connecting | snow | лампа, мигает |
| connected | snow | лампа `#E8B84A` (`loft-tray`) |
| error / route closed | snow | красный `#E24B4B` (`loft-tray-err`) |

В режиме multi действует то же правило, что в macOS §7: жёлтый, если жива хотя бы одна сессия; красный, если хотя бы одна в ошибке.

Мышь:

| Действие | Что открывается |
|----------|-----------------|
| Левый клик | панель трея (§3) |
| Правый клик | меню трея (§4) |
| Двойной клик | Открыть Loft (окно статуса) |

Подсказка при наведении: `Loft — Подключено: Офис` / `Loft — Нет активных подключений`.

## 3. Панель трея

Это popover из macOS §7.1 с тем же содержимым и тем же поведением: заголовок, Connect / Disconnect / Retry, Reset routes при взведённом hold, строки Connection / Внешний IP / Overlay / Route / SOCKS5, аккордеон при «Несколько», подвал Открыть Loft | Настройки | Выйти.

Отличия:

- Панель прижата к краю экрана со стороны панели задач, у области уведомлений. Если панель задач сверху или сбоку, панель трея открывается у того края.
- Стрелки-«хвостика» нет.
- Фон сплошной `#201c19`, без размытия.
- Закрывается при потере фокуса и по Esc.
- «Connection ›» открывает список профилей слева от панели (в macOS это `NSMenu`).

Размер — 300 × hug, как в macOS.

## 4. Меню трея

В Windows нет строки меню приложения. Меню macOS **Loft**, **Подключения** и **Инструменты** собраны в контекстное меню значка:

```
Отключить · Офис              (Подключить, когда закрыто)
Подключения              ›    профили: галочка на текущем, статус справа
───
Открыть Loft
Настройки
✓ Раздельная маршрутизация    тот же выключатель, что в Настройках
Маршруты
Журнал
───
Язык (Language)          ›    родные названия, галочка на текущем
О программе Loft
───
Завершить Loft
```

Иконки — те же, что в меню macOS (окно, шестерёнка, ветвление, документ, глобус). Меню **Правка** из macOS сюда не перенесено: правка открывается из списка Подключений.

## 5. Окна

Рамку и заголовок рисует приложение. Высота заголовка 32 px: знак трея 16 px, `Loft`, справа кнопки **Свернуть** и **Закрыть** по 46 px. Развернуть нет: размер окон фиксирован (macOS §11). Закрыть при наведении — красный `#C42B1C`. Скругление углов — 8 px. Тень — своя.

Закрытие окна не завершает Loft: агент остаётся в трее. Завершить — только из меню трея или панели трея (**Выйти**).

Размеры окон — как в macOS §11; к высоте добавляется заголовок 32 px.

## 6. Настройки

Вкладки и пункты — как в macOS. Отличаются два пункта вкладки «Общие»:

| macOS | Windows | Описание |
|-------|---------|----------|
| Открывать при входе (Login item) | **Запускать вместе с Windows** | В трее, без окна |
| Отображать значок в Dock: всегда / когда открыто окно / никогда | **Кнопка на панели задач**: всегда / когда открыто окно / никогда | Значок в трее остаётся |

«Расширенный журнал» вместо `loft-priv` пишет строки службы loft.

В конце вкладки «Общие» — два пункта, которых в macOS нет:

| Пункт | Описание | По умолчанию |
|-------|----------|--------------|
| **Открывать файлы .loft** | Двойной клик открывает Loft | вкл |
| **Открывать ссылки loft://** | Ссылки в браузере открывают Loft | вкл |

Файл или ссылка открывают импорт (как «Импорт» в Подключениях). Выключатель снимает регистрацию, включатель ставит заново. «По умолчанию» включает оба.

Установщик: на шаге установки та же опция — галочка «Открывать .loft и loft:// в Loft», **включена по умолчанию**. Снятая галочка = оба пункта в Настройках выключены.

## 7. Импорт, экспорт, обновление

- Импорт и экспорт — через стандартные диалоги Windows «Открыть» / «Сохранить как». Зона перетаскивания в макете показывает, что файл можно бросить на окно.
- Окно обновления: «Скачать и заменить эту копию». Проверка — GitHub latest, как в macOS. Скачивается `loft-<версия>-windows-x64.zip` или zip x86, каталог запущенного exe заменяется, процесс стартует снова. Копия в Program Files запрашивает администратора. Файл службы на диске заменяется; уже запущенная служба держит старый образ до перезапуска.
- Dist на теге `v*` публикует два portable zip и `loft-windows-<версия>-SHA256SUMS.txt`. `make release` дополнительно собирает установщики и раскладку Store.
  - Portable: `loft-<версия>-windows-x64.zip` и `loft-<версия>-windows-x86.zip`. Распаковать и запустить. Windows 7 SP1 и новее. Службу ставит первое включение туннеля.
  - Установщик: `loft-windows-x64-setup.exe` и `loft-windows-x86-setup.exe`. Копирует в Program Files, регистрирует службу, ярлык в меню Пуск и удаление. MSI нет. Тот же нижний порог ОС. Галочка «Открывать .loft и loft:// в Loft» включена; снятая пишет рядом с exe файл `assoc.off`, и первый запуск выключает обе ассоциации.
  - Канал GitHub — portable zip. Приложение читает последний релиз `a3app/loft`. Установщики не являются телом обновления.
  - Microsoft Store — отдельный пакет x64, Windows 10 версии 1809 и новее. В нём нет Wintun и нет `loft-svc`: пакет магазина не ставит драйвер ядра и службу LocalSystem. SOCKS работает. Обновления идут из Store. `make store` пишет `dist/clients/Windows/store/x64` с `AppxManifest.xml`. `makeappx` и подпись Partner Center делаются на Windows. Значение `Publisher` `CN=a3app` заменяется сертификатом магазина.

## 9. Тексты

Строки — общие паки macOS [`../../macOS/lang/`](../../macOS/lang/). Поверх них — [`lang/win.lang`](lang/win.lang): только ключи, которые в Windows звучат иначе (`login`, `login_d`, `dock`, `dock_d`, `diag_d`, `upd.offer.body`, `win.min`, `win.close`, `assoc_file`, `assoc_link` и их подписи, подписи сцен трея). Порядок поиска: Windows-пак языка → Windows-пак английский → пак macOS. Переведено на en / ru / zh; в остальных языках эти ключи пока английские.

В текстах, как и в macOS: *route*, *direct Internet*, *reset*; без «kill switch» и «shield».

## 10. Решения

Закрыто в дереве v1, каталог [`../`](../). Сборка и запуск: [`../README_ru.md`](../README_ru.md).

1. **UI.** C11, Win32, GDI. Без WebView и без системных тем. `_WIN32_WINNT=0x0601`. Сборки x86 и x64 через mingw-w64 (`-mwindows -static -municode`). Segoe UI и Consolas. В Windows 7 из коробки только Regular и Bold; UI запрашивает Medium и Semibold и принимает то, что подставит GDI. DPI — `GetDeviceCaps(LOGPIXELSX)` и `SetProcessDPIAware`. Манифест перечисляет Windows 7, 8, 8.1 и 10, `dpiAware` true, `asInvoker`. Идентификатора Vista нет. «О программе» показывает `LOFT_VERSION` из [`../VERSION`](../VERSION) (1.0.0), не строку версии macOS.
2. **Сеанс.** `loft-front.exe` рядом с `loft.exe`. Модуль — Go 1.26. Обычный Go 1.21+ под Windows 7 не собирает, поэтому front собирается патченным XTLS/go-win7 (`make front GO_WIN7=...`). Оболочка Go не линкует. Без `GO_WIN7` цель `make` этот бинарь пропускает. go1.27.3 этим тулчейном уже запускался на Windows 7 SP1 x64 в [`wintun-check`](../wintun-check/).
3. **TUN.** Только Wintun 0.14.1. Не songgao/water и не `netsh`. Служба создаёт адаптер с именем `Loft` и типом `Loft`, адрес ставит через `CreateUnicastIpAddressEntry`, MTU 1280 — через `SetIpInterfaceEntry`, маршруты — через `CreateIpForwardEntry2`. Пакеты идут в `\\.\pipe\loft-tun` в байтовом режиме: длина u32le и IP-пакет, максимум 65535. Стек в пространстве пользователя крутит `loft-front`. `WintunDeleteDriver` вызывается только из `--uninstall-driver`. GUID адаптера — те же 16 байт, что у `wintun-check` (`6c 6f 66 74 2d 77 69 6e 74 75 6e 2d 63 68 6b 01`); Windows показывает `{74666F6C-772D-6E69-7475-6E2D63686B01}`. Ёмкость сессии `0x400000`. Оболочка ставит адрес Overlay IP как /32. Если маршрут по умолчанию выключен, дополнительно уходит маршрут overlay /24.
4. **Служба.** Имя `loft`, отображаемое имя `Loft`, отдельный процесс, автозапуск, зависимость Tcpip. Бинарь `loft-svc.exe`. Управляющий канал `\\.\pipe\loft-ctl` (режим сообщений). MSI нет. `--install` поднимает права, когда их нет. SOCKS службу не требует; первое включение туннеля предлагает её поставить. SDDL канала: `D:P(A;;GA;;;SY)(A;;GA;;;BA)(A;;GA;;;IU)`. `tun-close` при включённом hold отвечает `ok held` и адаптер не трогает. `reset` всегда возвращает сохранённый IPv4-маршрут по умолчанию и DNS. Физический IPv4-маршрут по умолчанию снимается в снимок до подмены. DNS — значение `NameServer` у ключа интерфейса адаптера, затем `DnsFlushResolverCache` и `DhcpNotifyConfigChange`. Журнал `%ProgramData%\loft\svc.log`, потолок 1 МБ, перезапуска после сбоя нет.
5. **Ключи.** DPAPI `CryptProtectData` текущего пользователя, `%APPDATA%\loft\keys\<id>.bin`. В YAML профиля нет token, uuid и пароля. Экспорт `.loft` ключ включает и предупреждает. `loft-front` по-прежнему получает `-token` в командной строке, как на macOS.
6. **Хранилище и настройки.** Профили, активный id, файл экземпляра, настройки, маршруты и журнал — в `%APPDATA%\loft`, как в §8. Значения по умолчанию совпадают с клиентом macOS (язык ru, hold выключен, failover включён, split выключен, маршрут по умолчанию включён, общий SOCKS 1080, проверка обновления включена). На Windows добавляются ассоциации текущего пользователя для `.loft` и `loft://` (по умолчанию включены) и автозапуск (`HKCU\...\Run`, значение `Loft`, команда `"exe" --tray`). Проверка обновления читает последний релиз GitHub `a3app/loft` и, если тег новее и в релизе есть portable zip, заменяет эту копию из `loft-<версия>-windows-x64.zip` или zip x86. Dist подставляет в `LOFT_VERSION` корневой `VERSION`, чтобы тег совпал. Сборка Store GitHub не опрашивает.
7. **Что остаётся ограничением.** Маршруты по умолчанию IPv6 не снимаются. Wintun x86 на железе не проверен. Журнал службы за потолком не ротируется. Оболочка этого дерева слинкована, на Windows не запускалась.
