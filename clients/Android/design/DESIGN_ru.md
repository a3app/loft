# loft · клиент Android

[English](DESIGN.md) · **Русский** · [中文](DESIGN_zh.md)

Приложение для телефона и `VpnService`. Знак, палитра и Avenir Next: [`brand/`](../../../docs/brand/). Интерактивный макет: [`index.html`](index.html); у каждого состояния своя ссылка, например `index.html#edit-sstp`, `#settings-route`, `#home-off` (адрес меняется при переходах). Протокол: [docs/protocol_ru.md](../../../docs/protocol_ru.md). URI импорта: [docs/share_ru.md](../../../docs/share_ru.md).

Контейнер Java лежит в [`../app/`](../app/). Рабочую сессию ведёт Go внутри `LoftVpnService`, а не `loft-front`. Приложение реализует этот макет: Главная / Подключения / Правка / Скан / Настройки.

---

## 1. Продукт

Локальным входом служит системный VPN (`VpnService`). Одновременно активен один профиль: loft (`lt_…`, пароля нет), SSTP (логин + пароль), VLESS (`vless://`) или Trojan (`trojan://`).

v1: именованные подключения на диске, импорт/экспорт `.loft`, Подключить/Отключить, удержание (системными тумблерами Android), раздельная маршрутизация по спискам протокола. `select: auto` внутри YAML loft. Одновременно работает один туннель.

Файл `.loft` содержит **одно или несколько подключений**. Типы можно смешивать: `loft`, `sstp`, `vless`, `trojan`. В строке списка показаны хост и **тип · транспорт** (`loft · get`). Адрес loft записывается строкой `loft://`. Спецификация: [docs/share_ru.md](../../../docs/share_ru.md).

Обмен: отсканировать QR-код или загрузить файл/картинку с `loft://`, `sstp://`, `vless://`, `trojan://` или `.loft`.

Настройки Android показывают ту же строку VPN, которую поднимает приложение. Приложение не подменяет Настройки.

Адаптер написан на **Java 17**. gomobile и так генерирует Java, поэтому Kotlin runtime в этот процесс не загружаем. Макет сделан на HTML; рабочий GUI позже будет на Views (без Compose).

Android TV / Google TV — тот же `VpnService` и AAR, но во flavor Leanback. Макет для просмотра с дивана: [`tv/`](tv/). VIDAA / Tizen / webOS в задачу не входят.

### Раздельная маршрутизация

Модель macOS (DESIGN macOS §5): **зона** идёт через loft или в обход, **сервис** (имя + CIDR) только принадлежит зоне, **исключение** — CIDR, который не входит в зону и сохраняется при обновлении списка. Встроенные зоны — Local (в обход, LAN) и Global (через, `global.bat`); свои создаются в редакторе. На Android «через loft» означает маршруты `VpnService.Builder.addRoute`, «в обход» — `excludeRoute` (Android 13+); на старых версиях «в обход» вычитается из маршрутов туннеля. Пока туннель выключен, всё и так идёт напрямую.

**Зона Block.** Третья встроенная зона, рядом с Local и Global, без списка по умолчанию. Направление зоны — одно из трёх: **Через loft / В обход loft / Блокировать**; любая своя зона тоже может блокировать. Сети такой зоны заводятся в туннель, и клиент сам сразу отвечает отказом: TCP — сбросом соединения, остальное — ICMP «недоступен». Приложения не ждут тайм-аута. Блокировка действует только при включённом туннеле, как и вся раздельная маршрутизация. Исключения зоны не блокируются. В строке зоны и в списке зон — «Блокируется», под ней пояснение: «Пока включён loft, соединения к сетям этой зоны сразу получают отказ, а её домены не резолвятся.»

**Домены и местный DNS.** У сервиса, кроме сетей, есть **Домены** (домен включает поддомены; сервис может состоять из одних доменов). DNS отвечает сам клиент — резолвер в туннеле, который ОС получает вместо DNS ноды: имена из зон «в обход» он спрашивает у **местного DNS** (запрос идёт мимо туннеля), имена из зоны Block (и любой блокирующей) сразу получают NXDOMAIN, всё остальное уходит в DNS ноды. Настройки → Маршрут → **Местный DNS**: **Системный** (DNS сети, запомненный до подключения; по умолчанию), **Свой адрес** (например `77.88.8.8`) или **DoH** (URL). Работает только при включённом туннеле. В строке сервиса — «2 сети · 3 домена»; у сервиса из одних доменов вместо CIDR показаны первые домены. В редакторе «Сеть» поле **Домены** идёт после сетей, у исключения его нет.

Вход: Настройки → Маршрут → тумблер и золотая **Списки**. Экраны открываются внутри вкладки Настройки, вверху **←**. Набор экранов тот же, что на iOS: Списки (тумблер, вкладки зон с числом сервисов, строка `Global · Через loft`, поиск, строки сервисов, **+ Добавить**, Импорт · Экспорт · Репозиторий), Сеть (Маршрут / Исключение, сети, сервис, зона), Зоны, Зона (имя, направление, адрес списка + **Списки**, автообновление; своя — Удалить зону, сервисы → Global), Репозиторий, Каталог (Мир, Россия, Китай, Иран, Казахстан, Беларусь), Импорт (из файла через SAF), Экспорт (все зоны в одном файле loft-routes, лист «Поделиться»).

**Очистка.** Удаление срабатывает сразу. Внизу на 5 с появляется snackbar «Удалено: YouTube · **Отменить**», он возвращает всё как было. Отдельного диалога нет, кроме очистки зоны и исключений.

- **Свайп влево** по строке сервиса открывает красное **Удалить**.
- **Долгое нажатие** на строку включает выбор. Шапку заменяет панель: **✕**, «Выбрано: N», **Все** (все сервисы открытой зоны, повторное нажатие снимает выбор), **Удалить**. Строки получают кружок-отметку, тап по строке отмечает её.
- На экране **Сеть** у существующей записи внизу **Удалить сервис** (у исключения — **Удалить исключение**). Экран закрывается, появляется snackbar.
- **⋮** в навбаре Списков: **Выбрать** (тот же режим выбора) и **Очистить зону**. Диалог «Очистить Global?»: **Только свои (N)** и **Всё, включая список (M)**. «Всё» отвязывает список зоны: адрес и автообновление отключаются, иначе сервисы вернутся при обновлении. Исключения остаются. Если в зоне нет сервисов из списка, в диалоге одна строка **Удалить все**.

Сервис из списка (источник «список») при удалении не пропадает бесследно: его сети уходят в исключения зоны, иначе следующее обновление вернёт их обратно (правило macOS §5). Snackbar так и пишет: «… · сети списка — в исключениях». Свои сервисы удаляются насовсем.

**Исключения** живут на своём экране, а не в общем списке. Под списком сервисов идёт строка **Исключения · N ›**. Экран «Global · Исключения» (вверху **←**): подпись «Эти сети не ставятся и не возвращаются при обновлении списка», строки CIDR (моноширинный) с именем сервиса справа, тап — правка на экране Сеть. **Свайп влево** открывает **Вернуть**: исключение удаляется, и сеть придёт с ближайшим обновлением списка. **+ Добавить** открывает Сеть с выбранным «Исключение». Внизу **Очистить исключения** с диалогом.

## 3. Системный интерфейс Android

Не перекрашивать Настройки → Сеть и интернет → VPN. Макет показывает, как **loft** выглядит в *их* списке VPN: статус Подключено, тумблер управляет системным туннелем, а не служит вторым выключателем в нашем приложении.

Подключить вызывает `VpnService.prepare` один раз, затем `startForegroundService(LoftVpnService)`. Если пользователь выключил loft в Настройках, приложение показывает состояние «выкл».

Разрешение на VPN запрашивается один раз системным диалогом **Запрос подключения**. Дальше Подключить ничего не спрашивает.

Разрешение на камеру запрашивается системным листом при первом сканировании. Галерея открывается через системный Photo Picker (без широкого доступа к медиафайлам). Через SAF выбираются картинки, текст, YAML, `.loft`.

Фильтр intent `loft`: тап по `loft://…` предлагает импорт. Файлы `.loft` открываются тем же детектором.

### Жесты списка

| Жест | Действие |
|------|----------|
| Тап | Открыть подключение (Правка). Подключает компактная кнопка Подключить; если было активно другое подключение, оно сначала отключается. |
| Свайп влево | Удалить, с диалогом подтверждения. |
| Свайп вправо | Править. |
| Долгое нажатие | Меню: Править; Экспорт `.loft`, если строка выбрана; Удалить. |
| Экспорт | Лист: это подключение как `Name.loft`; QR `loft://` живого фронта; все подключения как `Family.loft`. |

Рабочая сессия — это **foreground service** (тип `systemExempted`, как положено VpnService на API 34+). В уведомлении: имя, тип · транспорт · IP оверлея, Отключить. На API 33+ один раз появляется ещё лист разрешения на уведомления.

**Без VPN — без интернета** на Android реализуется системными тумблерами **VPN всегда включён** и **Блокировать подключения без VPN**. Приложение открывает эту страницу Настроек, а тумблеры переключает сам пользователь.

Плитка быстрых настроек: один тап подключает или отключает активный профиль. Лампа горит = в сети.

## 4. Визуал

Те же токены, что на iOS и macOS: Ink `#1A1714`, Lamp `#E8B84A`, Paper `#E8DFD2`, Avenir Next. Оформление приложения — loft (тёмная бумага), не сиреневый Material You; компоненты — Material: нижняя панель навигации (активная вкладка — капсула лампы под иконкой), верхняя панель с «←» / «✕» и меню ⋮, FAB 56 dp со скруглением 16 dp, нижние листы и диалоги.

Шрифт: заголовки Demi, текст Regular, ключи Roboto Mono. В сети = окно лампы горит. Выкл = лампа погашена, каменная L.

Системные поверхности в макете (Запрос подключения, Настройки → VPN, уведомление, плитка) сохраняют штатное оформление Android, чтобы была видна граница продукта.
