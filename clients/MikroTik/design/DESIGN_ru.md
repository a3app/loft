# loft · пошаговый макет RouterOS

[English](DESIGN.md) · **Русский** · [中文](DESIGN_zh.md)

Интерактивный макет: [`index.html`](index.html). Фирменный стиль: [`brand/`](../../../docs/brand/). Интеграция: [docs/mikrotik_ru.md](../../../docs/mikrotik_ru.md).

Макет показывает путь оператора в Winbox / New Terminal и LAN-страницу `http://172.31.20.2:8090/`. Mangle, таблицы маршрутизации и address-list остаются за RouterOS. loft — контейнер, который держит сессию.

YAML по-прежнему лежит на диске, и LAN-страница его записывает.

---

## 1. Продукт

Один контейнер с именем `loft`. Один veth `172.31.20.2/24`. SOCKS5 работает с первой загрузки. Шлюз для LAN — только после строки `tun up` в логе.

Оператор:

1. Вставляет `check.rsc` в New Terminal.
2. Кладёт `loft.tar` и `client.yaml` на диск.
3. Вставляет `install.rsc`, ждёт `stopped`, запускает контейнер.
4. Открывает `http://172.31.20.2:8090/` — ключ участника, URL ноды, **исходящий интерфейс RouterOS** (`ether1`, `lte1`, `pppoe-out1`).
5. Если выход изменился, выполняет `/import disk1/loft/data/uplink.rsc` в New Terminal.
6. Направляет ноутбук в SOCKS `172.31.20.2:1080`.
7. Если в логе есть `tun up`, вставляет `policy.rsc` для списка LAN.

`.npk` вендора нет. Новой строки в Winbox «Интерфейсы / VPN» нет. SSTP и WireGuard остаются штатными клиентами RouterOS.

## 2. Экраны

| Экран | Что |
|-------|-----|
| Проверка | Имя, версия, `architecture-name`, пакет `container`, `device-mode`, диски. Если что-то красное, install не запускать. |
| Файлы | `<диск>/loft/loft.tar` и `<диск>/loft/data/client.yaml`. Токен и URL ноды хранятся в YAML. |
| Контейнер | Имя `loft`, veth-loft, `start-on-boot`, лог. Статус `running`. |
| SOCKS | Сразу после строки `socks5` в логе. Браузер и SSH — `172.31.20.2:1080`. |
| Панель :8090 | Статус, ключ, URL, фронт, **выход**. Пишет `client.yaml` и `uplink.rsc`. По желанию `listen.http_pass`. |
| Шлюз | `policy.rsc`: таблица `loft`, 0/0 через 172.31.20.2, список `loft-lan`, mangle обходит `172.31.20.0/24`. Скрыт, пока нет `tun up`. |
| Журнал | Хвост `/log print where topics~"container"`. Ключей в журнале нет. |

Простой вид (по умолчанию): Проверка → Файлы → Контейнер → Панель. Шлюз — во второй группе.

Выход — имя WAN-интерфейса в RouterOS. Контейнер по-прежнему привязан к `eth0`. Пустой выход означает таблицу RouterOS по умолчанию.

## 3. Системный интерфейс RouterOS

Winbox не перекрашиваем. Макет показывает, как **loft** выглядит *у них* в Container, Files и New Terminal: именованный контейнер, veth, таблица маршрутизации, которую оператор вставляет сам.

Раздел «VPN» в Winbox (SSTP, WireGuard, IPsec, L2TP) штатный; loft там не появляется.

## 4. Визуал

Те же токены loft, что на macOS: Ink `#1A1714`, Lamp `#E8B84A`, Paper `#E8DFD2`, Avenir Next. Рамка Winbox в макете светло-серая (их админка), чтобы оператор видел оба мира.

Шрифт: заголовки Demi, текст Regular, ключи SF Mono. L-знак — тот же контур 96×96, что на macOS: корпус цвета stone, окно slate — выключено, окно лампы — включено. Контейнер запущен — окно лампы горит. Остановлен — лампа погашена, L цвета stone.

В подвале показан живой путь: `http://172.31.20.2:8090/` на LAN-странице, `SOCKS 172.31.20.2:1080` на SOCKS, `/data/client.yaml · /data/uplink.rsc` на Подключении.
