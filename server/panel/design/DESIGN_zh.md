## 1. 产品

一台服务器，一个所有者。面板安装并配置 loft 节点及其周边组件。运营者未在 **软件包** 中选择的内容一律不安装。面板用户与 loft 成员是两回事：用户登录面板，成员持有 `lt_…` 密钥。

安装：一条命令（`curl | sh` 或 `.deb`），然后在浏览器中完成五步向导。第 5 步为首次选择软件包，默认不勾选任何项。

语言：俄语为源语言；`en.js` 与 `zh.js` 为每条俄语字符串提供英文和简体中文，`i18n.js` 替换已绘制页面的文本。页眉的 EN / RU / 中文 选择框（以及登录卡片、手机菜单和向导中的选择框）在本浏览器内切换 English / 俄语 / 中文；面板默认语言在“设置”中。若有俄语字符串缺少英文或中文，测试失败。

## 4. 网段：网络即可网管交换机

每个 loft 网络都呈现为一台交换机。成员即端口。端口只属于一个 VLAN（access）；节点不支持 trunk。模型即 `netconf.Network`，`network.conf` 之外不存任何东西。

| 标签页 | 内容 |
|--------|------|
| 端口与 VLAN | 前面板：网关端口，其后为成员端口。颜色 = VLAN，指示灯 = 在线，划线标签 = 已停用。多选 → 设 VLAN、启用、停用。VLAN 成员表（VLAN × 端口，点击移动）。VLAN 表。端口表 |
| 访问规则 | ACL 与 `peers` 生效后的 VLAN × VLAN 访问结果；部分放行（协议/端口/主机）在格内注明。有序 ACL 列表，↑↓，规则对话框实时显示配置行 |
| 网络设置 | CIDR、网关、地址池、`peers` hub/mesh/vlan、p2p、DNS、MTU（默认 1280）、会话计时、路由 |
| 配置 | 节点语法的 `network.conf`。双向同步：改文本即更新交换机，改交换机即重写文本。出错时显示行号及节点自身的报错 |

面板的解析与输出对应 `internal/netconf` 中的 `ParseCommands`、`RenderCommands`、`ParseACLLine`。面板输出必须经 Go 代码往返后保持不变。

草稿与已应用：所有改动先进入草稿。提示条显示差异行数；**变更内容** 显示带上下文的差异；**应用** 让节点即时重读网络；**撤销** 丢弃草稿。

## 5. 节点

标签页：基本（角色、listen、advertise、来自域名的证书、前端 get/ws/h2/quic/h3、`get_h2`）、伪装（decoy 列表、`mask` 与 `pbk`、掩护站点、请求路径）、中继与 CDN（`enrol`、`relays[]`、`cdn_peers`）、列表（下发给客户端的签名列表；出口规则复用）、访问（控制器公钥、共享令牌、更换令牌、trace）。

启用 decoy 时，QUIC 与 HTTP/3 置灰并注明原因。

## 6. 网络与 IP

**地址与路由。** 地址表：地址（主地址、面板添加、通道）、接口、网关、监听者、PTR。路由表：目标、经由、接口、来源（系统、面板、通道）。面板只增删自己的地址和路由，不动系统的。修改立即生效，若未在提示条上确认，2 分钟后自动撤销（服务器上的定时器，面板不在也会执行；重启同样丢弃未确认的修改）。面板自己的配置在 `/etc/loft-panel/net.json`，开机时应用。

**外部通道。** 分区按已安装的软件包显示；SSTP 与代理内置于 loft，始终可用。每行有开关、名称（其下为系统名与状态）（工作中、连接中、不可用、已关闭、等待授权）以及删除。名称可自由填写，最多 40 字，仅用于面板；系统名（`wg0`、`ovpn0`、`zt0`、`sstp0`、`px0`、`xr0`，取下一个空闲编号）由面板在创建时分配，之后不变。

| 分区 | 表格 | 对话框 |
|------|------|--------|
| WireGuard（软件包） | 连接、地址、对端、发送、接收、对端地址和端口、最近握手 | 私钥 + 生成密钥对、公钥、隧道内地址、监听端口；对端：名称、公钥与预共享密钥、地址和端口、允许的子网、保活；折叠：MTU、故障时。上传 `.conf` 自动填写 |
| VPN 连接 | 连接、VPN 类型、服务器、发送、接收、地址 | SSTP：服务器、用户、密码、认证（自动、MS-CHAP v2、PAP）、不校验证书。OpenVPN（软件包）：`.ovpn` 文本或上传、用户与密码；折叠：接收路由（从不接收默认路由） |
| ZeroTier（软件包） | 连接、网络、网络 ID、本地 ID、IP、发送、接收 | 网络 ID（16 位十六进制）、授权提示；折叠：从网络获取地址和路由 |
| 代理 | 连接、类型、地址、登录、发送、接收、经由 | HTTP / HTTPS / SOCKS5、地址:端口、无登录或用户与密码；折叠：经由连接、UDP（直连、经 SOCKS5、阻止） |
| Xray（软件包） | 连接、服务器、经由、发送、接收 | `vless://` `trojan://` `ss://` 链接并解析；经由 WireGuard、OpenVPN、ZeroTier 或代理连接 |

每个对话框都有 **用于访问互联网**（可在规则中选择该通道）和 **故障时**（直连、另一通道、阻止）。WireGuard、OpenVPN 与 ZeroTier 可 **在通道外部 IP 上接收入站连接**。密码和密钥保存后不再显示。

**出口规则**：成员、标签或 `node.conf` 中的地址列表 → 通道；自上而下检查，箭头调整顺序；“其余成员流量”一行决定其他流量的去向。行尾显示“故障时”链。服务器自身始终直连；ICMP 与发往节点的 DNS 查询也直连。

**经通道接收**：通道、外部地址、通道内地址、监听者。

实现：每个内核通道有自己的路由表和 `oif` 规则，因此只有绑定到该通道的节点套接字走它——服务器默认路由不变。WireGuard 子网加入主路由表。节点读取 `egress.conf` 并在不重启的情况下重新加载；SSTP 与代理由节点自己维持，Xray 为独立服务，每个通道一个本地 SOCKS 入口。

## 6a. loft 节点

选项卡：**基本**（状态：角色、版本、运行起始、TCP/UDP 443 上的监听者、成员密钥数；重启与服务日志；监听；角色、客户端地址与证书只读，在向导中修改；前端——前置 Web 服务器时 UDP/443 共用：带标记的 loft QUIC 交给节点，其他数据包交给 Web 服务器；GET 的 HTTP/2 连接数），**伪装**（节点后的 Web 服务器——第一个是面板自己的；握手伪装与 pbk 密钥；站点目录；请求路径），**中继与 CDN**（中继及其权重、前端与下线；谁可连接；状态、连接数与响应来自节点报告；Cloudflare 按按钮获取地址段），**列表**（域名、.后缀与子网的命名列表；创建、从文件加载、编辑），**访问**（控制器密钥、共享令牌、更换节点令牌、会话日志）。修改先进入草稿；“应用”会重启节点，中继无需重启。节点每 5 秒报告在线者：“成员”显示在线/总设备数与最近登录，“网段”点亮端口。

## 7. 软件包

表格：软件包、状态、版本、端口/磁盘、操作（设置、更新到、安装、开关、卸载）。没有服务的工具（WireGuard、OpenVPN、SSTP）显示“已安装”，无开关；基础项不可停用（面板经由它访问）。卸载前确认，可选“清除数据”。分组：基础（节点、网页服务器、面板；不可卸载）、协议服务端（Telegram MTProto 代理，基于 mtg；随后为基于 Xray-core 的 VLESS、Trojan、Shadowsocks）、VPN 客户端、邮件（服务器、Rspamd、网页邮箱）、防护（防护程序、fail2ban）。MTProto 软件包安装目录中钉死的 9seconds/mtg GitHub 发行版（SHA-256 写在目录里），监听 TCP 8448（443 属于 loft-node）；设置对话框提供给 Telegram 客户端用的 `tg://proxy` 链接。任务运行时 **正在执行** 卡片显示日志；结束后 **上一个任务** 及其日志在成功后保留 10 分钟，失败后保留到下一个任务。更新来自 GitHub Releases：模式（默认：检查并通知）、通道、时间窗、SHA256SUMS、回滚；发现新版本时出现“更新到 X”。“同时更新软件包”选项随 Xray 一起提供，它更新的正是 Xray。

## 8. 登录、向导、域名、邮件

- **登录**（`#login`）：全屏，用户名、密码、语言；“无法登录” → `sudo loft-panel passwd admin`。
- **向导**（`#setup`）：管理员 → 域名与 DNS（Cloudflare、DigitalOcean、Namecheap 或手动；面板将创建的记录）→ 证书（Let’s Encrypt，DNS-01 或 HTTP-01，进度）→ 首个成员（二维码与 `loft://`）→ 软件包（默认不勾选；反垃圾与网页邮箱在邮件服务器下出现；有所选择时面板打开“软件包”页显示安装进度）。可从设置中重新打开。
- **域名**：区域表、所选区域的记录（面板创建的有标记，IP 变化时自动更新）、证书；区域、记录（MX/SRV 优先级）、证书（名称、验证、用途）、导入 PEM、DNS 服务商对话框。
- **邮件**：独立的邮件域名列表（按名称输入，“域名”中的区域作为提示）；每个域名的服务器名为 mail.<域名>——MX、客户端 IMAP/SMTP、网页邮箱。域名对话框：接收邮件（停用的域名保留邮箱）、DKIM 签名（密钥由面板生成；选择器在“更多”中）、全部接收；删除时可选择是否清除邮件。邮箱（所有者、占用条、转发、状态）、别名与“全部接收”行；带取值的 DNS 记录（MX、mail.<域名> 的 A/AAAA、域名与服务器名的 SPF、DKIM、DMARC、PTR），对接 DNS 服务商的区域可“创建缺失项”——已有的 SPF 和 DMARC 不动；mail.<域名> 证书及“签发”；服务、队列与一天内计数、客户端设置。邮箱对话框：密码（可生成；保存后只显示一次）、容量、转发副本、仅发送、启用、客户端设置。若应用未通过 Postfix/Dovecot 检查，恢复原文件，顶部提示条显示错误并提供“重新应用”。
- **选择软件包**：预设（全部、保持现状）、搜索、分组；右侧显示状态文字和复选框；基础项锁定；反垃圾与网页邮箱只在邮件服务器下出现；底部统计将安装与卸载的数量；只有在卸载时才出现“清除数据”。
- **系统**：防护即 fail2ban（“守护”软件包），安装后显示：面板登录失败始终计入，ssh 与邮件登录可勾选，扫描器（请求 /wp-login.php、/.env 等）首次即封；封禁覆盖所有端口；面板自身的登录锁定沿用同样的数值；白名单会提示你的地址是否在内；手动封禁 24 小时、7 天或永久并填写原因（自己的地址、回环和白名单拒绝），封禁表显示原因与剩余时间及“解除”。备份：计划（每天或每周日 04:00，或手动）、保留份数、位置（存储或仅本服务器——服务器上始终保留最新两份）、内容（节点与面板必含，邮件可选）；副本以恢复短语的密钥加密——服务器只保存公钥一半，短语只显示一次（“已记下”）；历史记录含结果与“恢复”；恢复对话框：副本（历史、恢复前副本、文件）、部分（仅副本中含有的）、短语；替换前面板先备份当前状态。存储：S3（地址、桶与路径、密钥）、SFTP（服务器自己的密钥，记住主机密钥）、服务器上的目录；“检查访问”写入并删除探测文件。Linux 账户（root 及 UID ≥ 1000 的用户）：无 sudo / 需密码的 sudo / 免密 sudo、可选密码（用于 sudo；只显示一次）、SSH 密钥、临时锁定、删除（可连同主目录）；面板不允许服务器失去能用密钥登录并成为 root 的账户；表格说明会指出 sshd 是否接受密码登录。
- **用户**：用户对话框（角色、密码或 24 小时邀请——链接只显示一次，打开“面板邀请”页面；API 令牌签发/轮换/吊销——只显示一次；可登录），角色对话框中的“分区 × 无/查看/修改”矩阵；服务器对每个请求检查角色，菜单只显示可见分区。会话可结束，API 令牌行可吊销；通过面板和 API 的所有修改记入日志，可按“谁”筛选。
- **设置**：重新运行向导（从“域名与 DNS”开始）；面板地址只读，名称与证书在向导中修改；默认语言（英语、俄语、中文）；服务器时区（更新时间窗以此为准）；闲置退出与会话期限；通过外部 SMTP 发送通知（收件人、发件人、服务器、端口、加密、登录名、密码——保存后不再显示），事件：证书 14 天内到期、更新或回滚、节点未启动、计划备份失败；测试邮件。

## 9. 需要节点补充的能力

| 缺失 | 影响 |
|------|------|
| 状态 API（租约、会话、中继、流量） | 在线指示灯、最近登录、计数 |
