## 1. Продукт

Один сервер, один владелец. Панель ставит и настраивает ноду loft и то, что рядом с ней. Ничего не ставится, пока оператор не выберет это в **Пакетах**. Пользователи панели и члены сети loft — разные сущности: пользователь входит в панель, у члена ключ `lt_…`.

Установка: одна команда (`curl | sh` или `.deb`), затем мастер из пяти шагов в браузере. Шаг 5 — первый выбор пакетов; по умолчанию ничего не отмечено.

Языки: исходный — русский; `en.js` и `zh.js` сопоставляют каждой русской строке английскую и упрощённый китайский, `i18n.js` подменяет текст отрисованной страницы. Выбор EN / RU / 中文 в шапке (и выбор на экране входа, в меню на телефоне и в мастере) — English / русский / 中文 для этого браузера; язык по умолчанию — в Настройках. Тест падает, если у русской строки нет английской или китайской.

## 4. Сегменты: сеть — управляемый свитч

Каждая сеть loft выглядит как свитч. Член сети — порт. Порт входит в один VLAN (access); trunk ноде неизвестен. Модель — `netconf.Network`; вне `network.conf` ничего не хранится.

| Вкладка | Что |
|---------|-----|
| Порты и VLAN | Лицевая панель: порт шлюза, затем порты-члены. Цвет — VLAN, огонёк — в сети, зачёркнутая подпись — выключен. Выбор нескольких → VLAN, включить, выключить. Таблица членства (VLAN × порт, клик переносит). Таблица VLAN. Таблица портов |
| Правила доступа | Итог доступа VLAN × VLAN после ACL и `peers`; частичный доступ (протокол/порт/адрес) подписан в клетке. Список ACL по порядку, ↑↓, окно правила с живой строкой конфига |
| Настройки сети | Диапазон, шлюз, пул, `peers` hub/mesh/vlan, p2p, DNS, MTU (по умолчанию 1280), таймеры сессии, маршруты |
| Конфиг | `network.conf` в синтаксисе ноды. В обе стороны: правка текста меняет свитч, правка свитча переписывает текст. Ошибка — с номером строки и сообщением самой ноды |

Разбор и вывод в панели повторяют `ParseCommands`, `RenderCommands` и `ParseACLLine` из `internal/netconf`. Вывод панели обязан проходить через код на Go без изменений.

Черновик и применённое: всё копится в черновике. Плашка показывает, сколько строк отличается; **Что изменено** — разница с контекстом; **Применить** заставляет ноду перечитать сеть на лету; **Отменить** сбрасывает черновик.

## 5. Нода

Вкладки: Основное (роль, listen, advertise, сертификат из Доменов, фронты — по умолчанию GET; ws/h2/quic/h3 явно, `get_h2`), Маскировка (список decoy, `mask` и `pbk`, сайт-обложка, пути), Ретрансляторы и CDN (`enrol`, `relays[]`, `cdn_peers`), Списки (подписанные списки для клиентов; правила выхода ссылаются на них), Доступ (ключ контроллера, общий токен, смена токена, trace).

QUIC и HTTP/3 при включённом decoy показаны серыми с причиной.

## 6. Сеть и IP

**Адреса и маршруты.** Таблица адресов: адрес (основной, добавлен в панели, канал), интерфейс, шлюз, кто слушает, PTR. Таблица маршрутов: назначение, через, интерфейс, источник (система, панель, канал). Панель добавляет и убирает только свои адреса и маршруты; системные не трогает. Изменение применяется сразу и откатывается само через 2 минуты, если его не подтвердить на плашке (таймер на сервере, сработает и без панели; при перезагрузке неподтверждённое тоже откатывается). Своё панель хранит в `/etc/loft-panel/net.json` и применяет при загрузке.

**Внешние каналы.** Разделы — по установленным пакетам; SSTP и прокси встроены в loft и есть всегда. В строке — переключатель, название и под ним системное имя с состоянием (работает, подключается, не работает, выключен, ждёт авторизации), удаление. Название — любое, до 40 знаков, только для панели; системное имя (`wg0`, `ovpn0`, `zt0`, `sstp0`, `px0`, `xr0` — следующий свободный номер) назначает панель при создании, и оно не меняется.

| Раздел | Таблица | Окно |
|--------|---------|------|
| WireGuard (пакет) | подключение, адрес, пир, отправлено, принято, адрес и порт пира, последнее рукопожатие | частный ключ + генерация пары, публичный ключ, адрес в туннеле, порт прослушивания; пиры: имя, публичный и общий ключ, адрес и порт, разрешённые подсети, проверка активности; свёрнуто: MTU, проверка связи. Загрузка `.conf` заполняет окно |
| VPN-подключения | подключение, тип VPN, сервер, отправлено, принято, адрес | SSTP: сервер, пользователь, пароль, аутентификация (Авто, MS-CHAP v2, PAP), не проверять сертификат. OpenVPN (пакет): текст или загрузка `.ovpn`, пользователь и пароль; свёрнуто: получать маршруты (маршрут по умолчанию — никогда) |
| ZeroTier (пакет) | подключение, сеть, ID сети, локальный ID, IP, отправлено, принято | ID сети (16 hex), подсказка про авторизацию; свёрнуто: получать адреса и маршруты от сети |
| Прокси | подключение, тип, адрес, вход, отправлено, принято, через | HTTP / HTTPS / SOCKS5, адрес:порт, без входа или логин и пароль; свёрнуто: подключаться через, UDP (напрямую, через SOCKS5, блокировать) |
| Xray (пакет) | подключение, сервер, через, отправлено, принято | ссылка `vless://` `trojan://` `ss://` с разбором; подключаться через WireGuard, OpenVPN, ZeroTier или прокси |

В каждом окне — **Использовать для выхода в интернет** (канал можно выбрать в правилах) и **Проверка связи** (не проверять, ping или подключение TCP; адрес, интервал, неудач подряд до «нет связи»). WireGuard, OpenVPN и ZeroTier могут **принимать входящие на внешний IP канала**. Пароли и ключи после сохранения не показываются.

**Приоритеты подключений** — свой пункт меню в «Сети», две вкладки. **Списки приоритетов**: слева колонка списков (имя, под ним «Режим резервирования» или «Многопутевой режим»; у выбранного — карандаш и корзина; корзина недоступна, пока список выбран в правилах), внизу «+ Добавить список» (название, «Начать с» — пустого или копии, многопутевая передача). Карандаш раскрывает правку прямо в колонке: название, «Многопутевая передача», «Сохранить» / «Отменить». Справа — все подключения с «Использовать для выхода в интернет»: ручка перетаскивания (порядок), галочка «использовать», точка состояния, имя, системное имя · тип · состояние, «сейчас» у текущего (в резервировании), ограничение скорости (↓/↑ Мбит/с или —) и карандаш → окно «Ограничение скорости» (входящий и исходящий: отключено или 1…500 Мбит/с, общее на всех, кто выходит по списку). Под таблицей: «Добавлять новые подключения автоматически», «Если ни один не работает» (напрямую или блокировать), подсказка, через какой канал идёт трафик. Галочки, перетаскивание и поля применяются сразу, без кнопки «Сохранить». Резервирование: первый работающий канал, при сбое — следующий; многопутевая передача: новые соединения по очереди расходятся по всем работающим каналам. Канал пропускается, пока он выключен, не подключён или не проходит проверку связи («нет связи»). **Применение**: слева «Остальной трафик (N)» и списки с числом, справа «Члены сети» и «Теги» плашками; плашку перетаскивают на список слева — это правило выхода «член» или «тег» в этот список; правило члена важнее тега; у «Остального трафика» — выбор, куда он выходит (правило по умолчанию). Списки адресов остаются в правилах выхода на «Внешних каналах». Старые цепочки «при сбое» при обновлении становятся списками.

**Правила выхода**: член, тег или список адресов из `node.conf` → список приоритетов (или напрямую, блокировать); проверяются сверху вниз, стрелки меняют порядок; строка «Остальной трафик членов» — куда уходит всё прочее. Хвост строки — порядок каналов списка, ссылка на «Приоритеты подключений». Сам сервер всегда выходит напрямую; ICMP и DNS-запросы к ноде — тоже.

**Приём через канал**: канал, внешний адрес, адрес в канале, кто слушает.

Как устроено: у каждого канала ядра своя таблица маршрутов и правило `oif`, поэтому через канал идут только сокеты ноды, привязанные к нему, — маршрут сервера по умолчанию не меняется. Подсети WireGuard кладутся в основную таблицу. Нода получает `egress.conf` и перечитывает его без перезапуска; SSTP и прокси держит сама, Xray — отдельная служба с локальным SOCKS-входом на канал.

## 6а. Нода loft

Вкладки: **Основное** (состояние: роль, версия, работает с, кто на TCP/UDP 443, ключей членов; перезапуск и журнал службы; слушать; роль, адрес для клиентов и сертификат — только чтение, меняются в мастере; фронты — при веб-сервере UDP/443 общий: QUIC loft с меткой идёт ноде, чужие пакеты — веб-серверу; соединений HTTP/2 для GET), **Маскировка** (веб-серверы за нодой — первый свой у панели; маскировка рукопожатия и ключ pbk; каталог сайта; пути запросов), **Ретрансляторы и CDN** (список ретрансляторов с весом, фронтами и выводом; кто может подключиться; состояние, подключения и отклик — из отчёта ноды; Cloudflare с диапазонами по кнопке), **Списки** (именованные списки доменов, .суффиксов и подсетей; создать, загрузить из файла, править), **Доступ** (ключ контроллера, общий токен, смена токена ноды, журнал сессий). Изменения копятся в черновике; «Применить» перезапускает ноду, ретрансляторы — без перезапуска. Нода каждые 5 с сообщает, кто в сети: «Члены сети» показывают устройства в сети / всего и последний вход, «Сегменты» — огоньки.

## 7. Пакеты

Таблица: пакет, состояние, версия, порты / диск, действия (настройки, обновить до, установить, вкл/выкл, удалить). Утилита без службы (WireGuard, OpenVPN, SSTP) показывается как «установлен», без вкл/выкл; основа не выключается — через неё открыта панель. Удаление спрашивает подтверждение, с галочкой «стереть данные». Группы: Основа (нода, веб-сервер, панель; не удаляются), Серверы протоколов (прокси Telegram MTProto на mtg, позже VLESS / Trojan / Shadowsocks на Xray-core), VPN-клиенты, Почта (сервер, Rspamd, веб-почта), Защита (защитник, fail2ban). Пакет MTProto ставит зафиксированный релиз 9seconds/mtg с GitHub (SHA-256 в каталоге), слушает TCP 8448 (443 занят loft-node); в настройках — ссылка `tg://proxy` для клиентов Telegram. Карточка **Выполняется сейчас** с журналом, пока задание идёт; потом **Последнее задание** с журналом остаётся на 10 минут после успеха и до следующего задания после сбоя. Обновления из GitHub Releases: режим (по умолчанию — проверять и сообщать), канал, окно, SHA256SUMS, откат; при новом релизе появляется «Обновить до X». Галочка «обновлять и пакеты» появится вместе с Xray — его она и обновляет.

## 8. Вход, мастер, домены, почта

- **Вход** (`#login`): во весь экран, пользователь, пароль, язык; «Не могу войти» → `sudo loft-panel passwd admin`.
- **Мастер** (`#setup`): Администратор → Домен и DNS (Cloudflare, DigitalOcean, Namecheap или вручную; какие записи создаст панель) → Сертификат (Let’s Encrypt, DNS-01 или HTTP-01, ход выпуска) → Первый член сети (QR и `loft://`) → Пакеты (ничего не отмечено; антиспам и веб-почта появляются под почтовым сервером; если что-то выбрано, панель открывается на «Пакетах» с ходом установки). Из Настроек можно открыть заново.
- **Домены** (`#domains`): таблица зон и все сертификаты; строка зоны открывает её страницу `#domains/<зона>` со ссылкой «← Домены»: как ведётся DNS и срок регистрации, записи (созданные панелью отмечены и обновляются при смене IP; у ручной зоны — столбец «Проверка»: есть / нет / другое значение и кнопка «Проверить записи»; от 9 записей — поиск по имени, типу и значению и фильтр по типу), «Настройки зоны», сертификаты имён этой зоны с «Выпустить сертификат» для неё. Адрес страницы зоны можно сохранить: после входа панель откроет её же. Новый домен: зона (подсказки из зон провайдера), где управляется DNS — добавленный доступ или «Вручную», сразу создать A/AAAA для имён сервера и CAA; записи почты создаёт раздел «Почта». Удаление зоны спрашивает подтверждение: записи у провайдера остаются. Запись: у существующей тип и имя не меняются, приоритет для MX/SRV, TTL авто / 5 минут / 1 час / 1 день, «Обновлять при смене IP» для A/AAAA. Сертификат: имена, проверка HTTP-01 / DNS-01, где использовать (нода loft, панель, почта — при пакете почты; у выпущенного не меняется), «Выпустить заново»; сертификаты ноды и панели не удаляются. Загрузка PEM — с местом использования. DNS-провайдеры: таблица доступов с удалением, добавление проверяет доступ («Проверить и добавить»), для Namecheap — пользователь API и белый IP сервера.
- **Почта**: свой список почтовых доменов (вводятся по имени, подсказка — зоны из «Доменов»); у каждого имя сервера mail.<домен> — MX, IMAP/SMTP для программ, веб-почта. Окно домена: принимать почту (выключенный хранит ящики), подпись DKIM (ключ делает панель, селектор — в «Дополнительно»), «ловить всё»; удаление — с выбором, стирать ли письма. Ящики (владелец, заполненность, пересылка, состояние), псевдонимы и строка «ловить всё»; записи DNS со значениями (MX, A/AAAA mail.<домен>, SPF домена и имени сервера, DKIM, DMARC, PTR) с «Создать недостающие» для зон с DNS-провайдером — чужие SPF и DMARC не трогаются; сертификат mail.<домен> с «Выпустить»; службы, очередь и счётчики за сутки, настройки почтовых программ. Окно ящика: пароль (генерация; показывается один раз после сохранения), объём, пересылка копий, только отправка, включён, настройки почтовой программы. Если применение не прошло проверку Postfix/Dovecot, прежние файлы возвращаются, а сверху плашка с ошибкой и «Применить снова».
- **Выбор пакетов**: наборы (всё, как сейчас), поиск, группы; состояние словом и галочка справа; основа закрыта; антиспам и веб-почта видны только под почтовым сервером; внизу — сколько поставится и удалится; «стереть данные» — только если что-то удаляется.
- **Система**: защита — это fail2ban (пакет «Защитник»), блок виден, когда он установлен: неудачные входы в панель всегда, в ssh и почту — по галочке, сканеры (запросы к /wp-login.php, /.env и подобному) — с первого раза; блок на всех портах; те же числа действуют и на собственную блокировку входа панели; белый список с подсказкой, попадает ли туда ваш адрес; ручная блокировка на 24 ч, 7 дней или навсегда с причиной (свой адрес, петлю и белый список блокировать нельзя), таблица заблокированных с причиной и остатком, «Снять». Бэкап: расписание (ежедневно или по воскресеньям в 04:00, или вручную), сколько хранить, куда (хранилище или только этот сервер — на нём всегда две последние копии), состав (нода и панель всегда, почта по выбору); копия шифруется ключом фразы восстановления — сервер хранит лишь открытую половину, фразу показывает один раз («Записал»); история с итогом и «Восстановить»; окно восстановления: копия (из истории, копия перед восстановлением, из файла), части (только те, что в копии), фраза; перед заменой панель делает копию текущего состояния. Хранилища: S3 (адрес, бакет и путь, ключи), SFTP (вход по ключу сервера, ключ хоста запоминается), каталог на сервере; «Проверить доступ» пишет и стирает пробу. Учётки Linux (root и люди с UID от 1000): права без sudo / sudo с паролем / sudo без пароля, пароль по желанию (для sudo; показывается один раз), SSH-ключи, временная блокировка, удаление с домашним каталогом или без; панель не даст оставить сервер без учётки, которая входит по ключу и может стать root; подпись под таблицей говорит, включён ли в sshd вход по паролю.
- **Пользователи**: окно пользователя (роль, пароль или приглашение на 24 ч — ссылка показывается один раз и открывает страницу «Приглашение в панель», API-токен выпустить/перевыпустить/отозвать — токен показывается один раз, может входить), окно роли с матрицей раздел × нет/смотреть/менять; права проверяются на сервере для каждого запроса, меню показывает только видимые разделы. Сессии с завершением, строки API-токенов с отзывом; журнал всех изменений через панель и API с фильтром «Кто».
- **Настройки**: мастер установки заново (с шага «Домен и DNS»); адрес панели только для чтения — имена и сертификаты меняются в мастере; язык по умолчанию (английский, русский, китайский); часовой пояс сервера (по нему окно обновлений); выход при бездействии и срок сессии; хранить ключи членов (по умолчанию выключено — тогда панель держит секрет, чтобы снова показать ссылку, QR и .loft без перевыпуска; выключение стирает копию в панели, файл на ноде остаётся); уведомления через внешний SMTP (кому, отправитель, сервер, порт, шифрование, логин, пароль — не показывается после сохранения), события: сертификат истекает через 14 дней, обновление или откат, нода не запустилась, резервная копия по расписанию не удалась; пробное письмо.
- **Подвал и «О loft panel»**: внизу каждой страницы справа — «Работает на loft-panel <версия>» (кнопка, открывает «О loft panel») и «Made with love ♥ by A³» (имя, не переводится). Страница «О loft panel»: что делает панель, разработчик, открытые компоненты, версия. Версию отдаёт /api/state только вошедшим.
