# loft-panel

[English](README.md) · **Русский** · [中文](README_zh.md)

Веб-панель одного сервера loft: нода, её сети и члены, IP-адреса и внешние каналы, домены с DNS-записями и сертификатами, почта, пакеты, пользователи панели. Цель — поставить и настроить сервер loft без ручной правки файлов.

UX: [design/DESIGN_ru.md](design/DESIGN_ru.md). Интерактивный макет: [design/index.html](design/index.html).

## Состояние

Первый рабочий срез. По-настоящему работают:

- вход, сессии, первый владелец по коду установки, `loft-panel passwd` / `users`;
- **Сегменты сети**: `network.conf` ноды в виде свитча и в редакторе конфига, применение перечитыванием на лету (нода перечитывает файлы, переподключаются только затронутые члены) и автоматическим откатом;
- новый член получает настоящий ключ `lt_` в `members.keys`; у удалённого ключ пропадает при применении; панель может хранить копию ключа, чтобы снова показать ссылку, QR и `.loft` (Настройки, по умолчанию выключено);
- состояние ноды на обзоре;
- мастер установки: владелец, имена ноды и панели, сертификаты Let’s Encrypt, первый член сети, первые пакеты;
- **Пакеты**: установка, обновление, выключение и удаление пакетов из закрытого каталога (прокси Telegram MTProto, WireGuard, OpenVPN, ZeroTier, fail2ban; основа — нода, nginx и SSTP), журнал задания прямо на странице;
- **Нода loft**: node.conf с экрана (слушать, фронты, веб-серверы за нодой, маскировка, пути, ретрансляторы, диапазоны CDN, общий токен, журнал сессий), списки адресов, смена токена ноды, журнал службы; кто в сети — из отчёта ноды;
- **Пользователи**: роли с матрицей раздел × нет/смотреть/менять (проверяется на каждый запрос), приглашения, API-токены (`Authorization: Bearer lpt_…`), сессии, журнал изменений;
- **Сеть и IP**: адреса и маршруты сервера (изменение откатывается через 2 минуты без подтверждения); внешние каналы — WireGuard, SSTP, OpenVPN, ZeroTier, HTTP/HTTPS/SOCKS5-прокси, Xray — и правила выхода по члену, тегу или списку адресов с запасными; приём через канал;
- **Обновление из релизов**: нода и панель из GitHub Releases со сверкой SHA256SUMS и откатом, если службы не поднялись.

Остальные экраны показывают пустое состояние.

## Размещение

```
server/cmd/loft-panel       веб-сервер, свой пользователь, без привилегий
server/cmd/loft-panel-adm   root-помощник (Linux), unix-сокет, фиксированный список операций
server/panel/web            HTTP: /api, вход, встроенный UI (ui/index.html + ui/live.js)
server/panel/adm            что делает помощник: network.conf, members.keys, systemctl
server/panel/admproto       протокол панель ↔ помощник
server/panel/catalog        пакеты, которые панель может ставить (ключи, имена apt, бинарники с GitHub, репозитории, юниты)
server/panel/auth           argon2id, сессии, ограничения входа
server/panel/store          users.json, settings.json, member-keys.json
server/panel/debian         install.sh, .deb, юниты systemd, сайт nginx
server/panel/devstand       настоящая панель и помощник на ноутбуке (systemctl подменён)
server/panel/design         UX и макет
```

`web/ui/index.html` собирается: `make panel-ui` копирует `design/index.html` и подключает `live.js`, который там, где есть бэкенд, меняет пример на запросы к API. Туда же копируются `en.js`, `zh.js` и `i18n.js` (исходный русский, английский и упрощённый китайский). Макет, открытый с диска, остаётся макетом.

## Установка

Сначала ставится панель, и она поднимает ноду: в тарболе лежит loft-node (`node/`), и он ставится, если ноды на сервере нет. На сервер с уже работающей нодой панель ставится поверх.

```bash
make dist-panel     # dist/panel/linux-{amd64,arm64}: тарбол с install.sh и .deb
sudo sh install.sh --host panel.example.net        # из распакованного тарбола
sudo apt install ./loft-panel_VERSION_amd64.deb    # или пакетом (Depends: loft-node)
```

Оба способа создают пользователя `loft-panel`, ставят nginx с сайтом панели на 127.0.0.1:8443, направляют туда decoy ноды с `decoy_proxy enable` (`loft-panel-adm wire-node`; decoy на чужой сайт не трогается), запускают обе службы и печатают код установки. Повторный запуск — обновление; `--uninstall` / `--remove` убирают.

make panel          # loft-panel (для этой машины) и loft-panel-adm (linux)

```

          └─ всё остальное ──▶ nginx 127.0.0.1:8443 ──▶ панель 127.0.0.1:8091, веб-почта, Xray по SNI
:80   nginx (ACME HTTP-01)
:8448 прокси Telegram MTProto (если пакет установлен)
```

## Защита

- Помощник пускает только uid панели (`SO_PEERCRED`) на сокете 0660, отвергает неизвестные операции и лишние поля JSON, ограничивает размер запроса.
- `network.conf` проверяется парсером самой ноды до записи. Запись атомарная, с fsync; прежний файл остаётся как `network.conf.prev`.
- Применение указывает SHA-256 файла, с которого начата правка, — два редактора не затрут друг друга.
- Применение перечитывает настройки ноды (SIGHUP; если в юните ноды нет ExecReload — перезапуск). Если `loft-node` через несколько секунд не активна, прежние `network.conf` и `members.keys` возвращаются, нода перечитывает их снова.
- Пакеты: браузер передаёт только ключи каталога; имена apt, репозитории, ключи подписи (встроены в бинарник), SHA-256 тарбола с GitHub, юниты и каталоги данных берутся из каталога. Помощник выполняет задание во временном юните `loft-panel-job` (`systemd-run`): по одному, вне своей песочницы, задание переживает перезапуск панели и самого помощника. `job.json` и `job.log` лежат в `/var/lib/loft-panel-adm`.
- Обновление ставит только релиз, найденный последней проверкой (старый тег со страницы не пройдёт). Скачанное должно совпасть с `SHA256SUMS` релиза. Если после установки нода или панель не активны, установка из архива возвращает сохранённые бинарники, а установка из .deb ставит заново .deb работающей версии. Режим по умолчанию — проверять и сообщать.
- Первому владельцу нужен код из `/var/lib/loft-panel/setup.code` — первый случайный посетитель панель не захватит.
- Сессия — cookie HttpOnly, SameSite=Strict (Secure за HTTPS) плюс CSRF-токен в заголовке. Неизвестный `Host` получает 421.
- Неудачные входы блокируют адрес клиента (5 за 10 мин → 24 ч). Нода передаёт его nginx при `decoy_proxy enable`. Без этого все клиенты видны как 127.0.0.1, и неудачи только замедляют этот логин (до 30 с), а не запирают всех.

## Что нужно от ноды

| Чего нет | Что блокирует |
|----------|---------------|
| API состояния (аренды, сессии, ретрансляторы, трафик) | огоньки «в сети», последний вход, счётчики |
| Несколько сетей на ноде | вторую сеть в Сегментах |
