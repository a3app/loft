# loft-panel

[English](README.md) · **Русский** · [中文](README_zh.md)

Веб-панель для одного сервера loft: нода, её сети и участники, IP-адреса и внешние каналы, домены с DNS-записями и сертификатами, почта, пакеты, пользователи панели. Цель — поставить и настроить сервер loft без ручной правки файлов.

UX: [design/DESIGN_ru.md](design/DESIGN_ru.md). Интерактивный макет: [design/index.html](design/index.html).

## Состояние

Первый рабочий срез. По-настоящему работают:

- вход, сессии, первый владелец по коду установки, `loft-panel passwd` / `users`;
- **Сегменты сети**: `network.conf` ноды в виде свитча и в редакторе конфига; применение с перечитыванием на лету (нода перечитывает файлы, переподключаются только затронутые участники) и автоматическим откатом;
- новый участник получает настоящий ключ `lt_` в `members.keys`, а у удалённого ключ при применении исчезает; ссылку, QR и `.loft` можно показать снова: панель берёт ключ у ноды и своей копии не хранит;
- состояние ноды на обзоре;
- мастер установки: владелец, домен и DNS (Cloudflare, DigitalOcean, Namecheap или вручную; панель создаёт A/AAAA и CAA), сертификаты Let’s Encrypt, первый участник сети, первые пакеты;
- **Домены**: зоны, DNS-записи (через API провайдера или вручную, с проверкой ручных записей), сертификаты Let’s Encrypt (HTTP-01 и DNS-01) и загрузка PEM; автоматические записи A/AAAA следуют за адресами сервера;
- **Пакеты**: установка, обновление, выключение и удаление пакетов из закрытого каталога (прокси Telegram MTProto, WireGuard, OpenVPN, ZeroTier, fail2ban; основа — нода, nginx и SSTP), журнал задания прямо на странице;
- **Нода loft**: node.conf с экрана (слушать, фронты, веб-серверы за нодой, маскировка, пути, ретрансляторы, диапазоны CDN, общий токен, журнал сессий), списки адресов, смена токена ноды, журнал службы; список тех, кто в сети, берётся из отчёта ноды;
- **Пользователи**: роли с матрицей раздел × нет/смотреть/менять (проверяется на каждый запрос), приглашения, API-токены (`Authorization: Bearer lpt_…`), сессии, журнал изменений;
- **Интернет**: подключения (WireGuard, SSTP, OpenVPN, ZeroTier, HTTP/HTTPS/SOCKS5-прокси, Xray) и правила выхода; приоритеты подключений — политика по умолчанию, без доступа и свои политики доступа, применение политик; адреса и маршруты сервера (если изменение не подтвердить, через 2 минуты оно откатывается);
- **Почта**: почтовые домены, ящики, DNS-записи и сертификат mail.<domain> (когда установлен пакет почты);
- **Система**: fail2ban, шифрованные копии и учётные записи Linux;
- **Обновление из релизов**: нода и панель из GitHub Releases со сверкой SHA256SUMS и откатом, если службы не поднялись.

## Размещение

```
server/cmd/loft-panel       веб-сервер, свой пользователь, без привилегий
server/cmd/loft-panel-adm   root-помощник (Linux), unix-сокет, фиксированный список операций
server/panel/web            HTTP: /api, вход, встроенный UI (ui/index.html + ui/live.js)
server/panel/adm            что делает помощник: network.conf, members.keys, systemctl
server/panel/admproto       протокол панель ↔ помощник
server/panel/catalog        пакеты, которые панель может ставить (ключи, имена apt, бинарники с GitHub, репозитории, юниты)
server/panel/auth           argon2id, сессии, ограничения входа
server/panel/store          users.json, settings.json
server/panel/debian         install.sh, .deb, юниты systemd, сайт nginx
lab/devstand                настоящая панель и помощник на ноутбуке (systemctl подменён)
server/panel/design         UX и макет
```

`web/ui/index.html` генерируется: `make panel-ui` копирует `design/index.html` и подключает `live.js`, который там, где есть бэкенд, заменяет демонстрационные данные запросами к API. Туда же копируются `en.js`, `zh.js` и `i18n.js` (исходный русский, английский и упрощённый китайский). Макет, открытый с диска, остаётся макетом.

## Установка

Сначала ставится панель, а она уже поднимает ноду: в тарболе лежит loft-node (`node/`), и он устанавливается, если на сервере ноды ещё нет. На сервер, где нода уже работает, панель ставится поверх.

```bash
make dist-panel     # dist/panel/linux-{amd64,arm64}: тарбол с install.sh и .deb
sudo sh install.sh --host panel.example.net        # из распакованного тарбола
sudo apt install ./loft-panel_VERSION_amd64.deb    # или пакетом (Depends: loft-node)
```

Оба способа создают пользователя `loft-panel`, ставят nginx с сайтом панели на 127.0.0.1:8443, направляют туда decoy ноды с `decoy_proxy enable` (`loft-panel-adm wire-node`; decoy, ведущий на чужой сайт, не трогают), запускают обе службы и печатают код установки. Повторный запуск обновляет установку, а `--uninstall` / `--remove` её удаляют.

          └─ всё остальное ──▶ nginx 127.0.0.1:8443 ──▶ панель 127.0.0.1:8091, веб-почта, Xray по SNI

## Защита

- Помощник на сокете 0660 принимает только uid панели (`SO_PEERCRED`), отвергает неизвестные операции и лишние поля JSON и ограничивает размер запроса.
- Перед записью `network.conf` проверяется парсером самой ноды. Запись атомарная, с fsync; прежний файл остаётся как `network.conf.prev`.
- При применении указывается SHA-256 файла, с которого начиналась правка, поэтому два редактора не затрут изменения друг друга.
- При применении нода перечитывает настройки (SIGHUP; если в юните ноды нет ExecReload, она перезапускается). Если через несколько секунд `loft-node` не активна, прежние `network.conf` и `members.keys` возвращаются на место и нода перечитывает их снова.
- Пакеты: браузер передаёт только ключи каталога; имена apt, репозитории, ключи подписи (встроены в бинарник), SHA-256 тарбола с GitHub, юниты и каталоги данных берутся из каталога. Помощник выполняет задания во временном юните `loft-panel-job` (`systemd-run`): по одному и вне своей песочницы, так что задание переживает перезапуск панели и самого помощника. `job.json` и `job.log` лежат в `/var/lib/loft-panel-adm`.
- Обновление ставит только релиз, найденный последней проверкой (старый тег со страницы не пройдёт). Скачанное должно совпасть с `SHA256SUMS` релиза. Если после установки нода или панель не активны, установка из архива возвращает сохранённые бинарники, а установка из .deb заново ставит .deb работавшей версии. Режим по умолчанию — проверять и сообщать.
- Первому владельцу нужен код из `/var/lib/loft-panel/setup.code`, поэтому первый случайный посетитель не сможет захватить панель.
- Сессия держится на cookie HttpOnly, SameSite=Strict (Secure за HTTPS) и CSRF-токене в заголовке. Неизвестный `Host` получает 421.
- Неудачные попытки входа блокируют адрес клиента (5 за 10 мин → 24 ч). Нода передаёт этот адрес в nginx при `decoy_proxy enable`. Без этого все клиенты видны как 127.0.0.1, и неудачные попытки лишь замедляют вход под этим логином (до 30 с), а не блокируют всех.

## Что нужно от ноды

| Чего нет | Что блокирует |
|----------|---------------|
| API состояния (аренды, сессии, ретрансляторы, трафик) | индикаторы «в сети», последний вход, счётчики |
| Несколько сетей на ноде | вторую сеть в Сегментах |
